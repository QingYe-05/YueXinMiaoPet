# 一、核心目标

彻底取消用户手动设置经纬度的方式。

天气地区选择改成：

`省（直辖市/自治区） → 市（州/盟/地区） → 县（区/县级市/旗）`

三级联动。

例如：

`河南省 → 郑州市 → 金水区`

`广东省 → 深圳市 → 南山区`

`北京市 → 北京市 → 海淀区`

`上海市 → 上海市 → 浦东新区`

`内蒙古自治区 → 呼和浩特市 → 新城区`

`新疆维吾尔自治区 → 乌鲁木齐市 → 天山区`

必须覆盖中国大陆完整行政区划数据。

重点要求：

- 所有省级行政区
- 所有地级行政区
- 所有县级行政区
- 市辖区
- 县
- 县级市
- 自治县
- 自治旗
- 旗
- 林区等现有县级单位

不要只覆盖热门城市。

不能出现：

- 北京只有北京市，没有区
- 上海没有浦东新区
- 重庆没有区县
- 广东只有广州深圳
- 新疆、西藏、内蒙古数据不完整

# 三、新行政区数据结构

建议使用本地 JSON：

`src\YueXinMiaoPet\Data\china_administrative_divisions.json`

结构不要使用简单字符串数组。

推荐：

```json
[
  {
    "code": "410000",
    "name": "河南省",
    "level": "province",
    "children": [
      {
        "code": "410100",
        "name": "郑州市",
        "level": "city",
        "children": [
          {
            "code": "410105",
            "name": "金水区",
            "level": "county"
          }
        ]
      }
    ]
  }
]
```

必须保留：

- code
- name
- level
- children

行政区 code 优先使用标准行政区划代码。

Weather 查询时优先使用行政区代码，而不是仅使用中文名称。

# 四、数据来源要求

不要凭记忆手写全国行政区数据。

请联网搜索并使用可靠、公开、可验证的数据源进行生成和校验。

如果官方行政区划和天气服务商支持区域存在差异：

以最新正式行政区划为基础数据。

天气接口不支持的特殊行政区，单独做天气查询 fallback。

# 五、行政区完整性自检

必须编写一个数据自检工具。

建议：

`tools/validate_china_regions.py`

或者：

`tools/validate_china_regions.ps1`

检查：

1. 是否有重复行政区 code
2. 是否有重复同级名称
3. 是否有 province 无 children
4. 是否有 city 无 children
5. 是否存在空 name
6. 是否存在空 code
7. 是否存在错误层级
8. 是否存在重复县区
9. 是否存在明显缺少的省份
10. 是否存在直辖市结构异常
11. 是否存在 county 被错误挂到其他 city
12. 是否存在孤立节点

输出：

```text
Province count:
City count:
County count:
Duplicate codes:
Missing parent:
Empty children:
Validation result:
```

不要把全国总数量硬编码为某个固定数字。

因为行政区划可能调整。

而是：

- 统计当前数据量
- 和在线参考数据进行比较
- 输出差异
